# 文档状态与路线索引

更新时间：2026-05-09

本文用于解决仓库中文档跨阶段积累后出现的前后矛盾问题。后续 AI 或组员接手时，应先读本文，再读其他文档。

如果只是想找文档入口和按任务阅读路径，先看 [文档目录向导](README.md)。本文更偏“路线判定”和“文档冲突时以谁为准”。

## 1. 当前有效路线

当前项目主线以 `app/` 的非 Blockly 自研积木应用为准：

```text
app/ 非 Blockly 自研积木主线
→ self-desktop/ 或浏览器应用窗口承载桌面演示
→ openharmony-port/ 使用 ArkWeb 加载 app/ 静态资源
```

`desktop/` 的 Blockly + Electron 工程保留为技术验证和参考资产，不再作为当前最终产品外观主线。它可以参考 TypeScript 分层、Blockly 序列化、Electron 打包经验，但不要把 Blockly 默认拼图外观、右侧拼图连接方式或其旧布局当成当前需求。

## 2. 已弃用或降级的旧方向

| 旧方向 | 当前状态 | 说明 |
| --- | --- | --- |
| Blockly 作为正式主线 | 已降级为技术验证 | 正式产品继续围绕 `app/` 的自研长方体积木推进。 |
| 固定“右侧上机器状态、右侧下数据流动画”布局 | 已弃用 | 右侧现在是可收合辅助栏，包含机器/代码/说明页签。 |
| 独立抽象数据流动画面板 | 已暂停/移除 | 当前改为围绕寄存器、内存、PC 的机器状态格动画。 |
| PC 在机器状态中占一整块大卡片 | 已弃用 | PC 已迁移到顶部执行进度条旁的小型显示。 |
| 动画表达式漂浮在页面右上角 | 已弃用 | 表达式应挂载到机器页顶部 `state-animation-dock`。 |
| OpenHarmony 展示一直占据机器页顶部 | 已调整 | 执行动画时表达式临时取代 OpenHarmony 展示，结束后恢复。 |
| OpenHarmony 第一版做 ArkUI 原生重写 | 暂不采用 | 当前先用 ArkWeb 加载 `app/` 静态页面。 |

## 6. 后续维护规则

- 旧文档不要轻易删除，因为它们记录了阶段性决策和可复盘依据。
- 发现旧文档与当前路线冲突时，优先在文档开头加“状态说明”，说明其哪些部分已弃用。
- 新增文档时，同步更新 `docs/README.md` 和本文档状态分类。
- 新功能完成后，应同步更新 `docs/下一阶段版本计划.md` 或对应专题文档。
- 与 OpenHarmony 相关的经验应写入 `openharmony-port/docs/OH开发经验与AI接手须知.md`，不要只写在聊天记录里。

## 7. 2026-05-11 补充：Windows 桌面版同步入口

本轮新增 `docs/2026-05-11_UI交互改动与Windows桌面版同步说明.md`，用于记录从上次提交到本次提交之间，围绕 OpenHarmony 真机调试反馈形成的 UI 与交互改动。

该文档不是只服务 OpenHarmony，它同时说明哪些改动应同步回 Windows 桌面版：

- OpenHarmony 展示与普通执行动画的互不抢占。
- 重置、上步、下步、自动播放、编辑撤销之间的职责边界。
- 数据演示卡片增加“寄存器 / 存储器 / PC”目标说明。
- 辅助栏高度调节、内部滚动、动画卡片拖动定位。
- 底部日志抽屉、页面高度和白屏问题的布局修正。
- 原生拖拽动画在 OpenHarmony 上仍会闪退，因此 OH 继续保留兼容拖拽/点击填槽方案，Windows 桌面版可继续保留完整拖拽体验。

后续如果要把这些体验优化到 Windows 桌面版，建议优先阅读该文档，再对照 `app/index.html`、`app/styles.css`、`app/src/app.js` 和 `app/src/state-animation.js`。
