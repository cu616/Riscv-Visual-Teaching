### OpenHarmony 移植原型

- `openharmony-port/` 单独承载 OpenHarmony ArkTS 壳，不直接混入 `app/` 主线目录。
- `openharmony-port/entry/src/main/ets/pages/Index.ets` 使用 ArkWeb 加载 `$rawfile('app/index.html')`。
- `openharmony-port/entry/src/main/resources/rawfile/app/` 保存从 `app/` 静态资源化得到的页面、样式和脚本。
- `openharmony-port/entry/src/main/resources/rawfile/app/src/datapath.js` 替换为轻量占位实现，可见数据流动画区域已在移植 CSS 中隐藏。
- `openharmony-port/entry/src/main/resources/rawfile/app/openharmony-bridge.js` 预留 Web 层桥接入口。
- ArkTS 侧 `OpenHarmonyBridge` 已预留 `getRuntimeInfo`、`saveCase`、`loadCase` 方法；其中保存/导入暂时返回“原生文件接口待实现”，用于后续接入 OpenHarmony 文件选择器和持久化能力。
- `openharmony-port/scripts/sync-rawfile.mjs` 新增静态资源同步脚本，可从 `app/` 重建 rawfile 页面并自动恢复移植版补丁。
- `openharmony-port/scripts/smoke-openharmony-port.mjs` 新增 rawfile 结构烟测，检查 ArkTS 入口、rawfile 页面、桥接脚本、数据流占位、AppScope 资源和 OpenHarmony SDK 字段类型是否齐备。
- `openharmony-port/build-profile.json5` 已按当前 OpenHarmony SDK API 24 修正：`runtimeOS` 为 `OpenHarmony` 时，`compileSdkVersion`、`compatibleSdkVersion`、`targetSdkVersion` 均使用数值 `24`。
- `openharmony-port/AppScope/resources/base/` 已参考 `ohos_electron_hap/` 补齐应用级字符串、图标和 configuration，避免 DevEco 索引 AppScope 资源时失败。
- `docs/OrangePi_RV2_X1_用户手册_v1.1.pdf`、`docs/OPI RV2 V1_1_SCH_20250508(1).pdf`、`docs/Ky X1芯片手册.pdf` 已加入仓库作为 RV2 / X1 硬件资料参考。

## 5. 当前验证命令

已通过：

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run smoke
npm.cmd run oh:sync
npm.cmd run oh:smoke
npm.cmd run oh:check
```

`npm.cmd run smoke` 会在独立端口启动 `app/` 静态服务，检查首页关键 UI 锚点，并拉取首页引用的 CSS 与 JS 资源。它不依赖浏览器自动化库，适合作为无人值守开发的第一层白屏排查。

`npm.cmd run oh:smoke` 检查 OpenHarmony 移植目录的静态结构，不等价于 DevEco Studio 构建或香橙派真机运行。真正的 ArkWeb 渲染、JSBridge 调用和 HDC 安装仍需要在 OpenHarmony 开发环境中验证。

## 6. 当前剩余风险

- 自由小积木吸附手感需要人工视觉反馈。
- 立即数双击编辑已改为页面内浮层输入，但仍需要人工确认位置和手感。
- 初始状态和教学备注已经进入保存导入闭环，但仍需要人工用真实案例确认演示体验。
- “上一步”当前回退的是机器执行快照，不是撤销积木编辑。
- 标签帽、指令外框、机器状态网格已按最新反馈调整，仍需要人工看视觉比例。
- 运行时编辑锁是第一版，后续如果需要可细分为“允许滚动但不允许拖拽/编辑”。
- 自动整理步骤栈会把主列附近释放的指令统一排到 `x=36`，如果后续需要自由布局，可增加开关。
- 指令重叠整理是第一版网格化规则，当前只在明显重叠时触发，复杂布局下可能还需要按实际手感调整行距和列距。
- 结构化备注已保存导入，但需要用真实课堂案例确认字段名称是否顺手。
- `app/src/app.js` 仍包含 DOM 事件绑定和吸附目标查找，后续可继续拆分。
- 当前 HTTP 烟测只能覆盖服务启动、HTML 主结构和静态资源 200，不能替代真实拖拽手感验收。
- Electron 原生窗口仍未修复，当前稳定入口是 Edge / Chrome 应用窗口模式。
- OpenHarmony 移植版尚未接入原生文件保存/导入；当前只是 JSBridge 方法预留。
- OpenHarmony 移植版尚未在香橙派真机通过 HDC 部署验证；需要后续用 DevEco Studio 或 hvigor + hdc 完成构建、签名、安装和日志排查。
