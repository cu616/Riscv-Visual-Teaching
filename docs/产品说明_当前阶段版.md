# 产品说明：RISC-V 指令集可视化教学桌面软件

更新时间：2026-05-01

## 1. 产品定位

本软件面向 RISC-V 初学者、计算机组成原理课程学习者和课堂演示场景，目标是把抽象的汇编指令执行过程转化为可拼接、可观察、可解释的教学体验。

当前阶段的软件是：

```text
大创比赛草案演示程序 / 构想验证原型
```

不是最终可交付的完整桌面软件。当前重点是证明产品构想成立：

- 学生能用积木构造 RISC-V 指令。
- 系统能生成结构化指令和汇编文本。
- 模拟器能单步执行指令。
- 机器状态能同步展示寄存器、内存和 PC。
- 数据流动画能解释每条指令为什么产生这样的状态变化。

## 2. 核心教学问题

RISC-V 汇编教学中常见困难包括：

1. 指令格式抽象，初学者难以区分 `rd`、`rs1`、`rs2`、`imm`。
2. 访存指令如 `lw rd, imm(rs1)` 容易把偏移量和寄存器顺序看错。
3. `x0` 恒零寄存器等架构规则不直观。
4. 条件分支和跳转对 PC 的影响不容易观察。
5. 逻辑运算和移位运算需要结合二进制位模式理解。
6. 传统文本汇编缺少即时可视化反馈。

本软件通过“积木构造 + 单步执行 + 数据流动画 + 机器状态展示”解决这些问题。

## 3. 目标用户

### 3.1 学生

需要：

- 低门槛理解 RISC-V 指令格式。
- 通过拖拽和观察建立直觉。
- 在错误操作时获得解释。

### 3.2 教师 / 助教

需要：

- 快速加载示例案例。
- 课堂上逐步演示寄存器、内存、PC 的变化。
- 用可视化动画解释指令执行路径。

### 3.3 大创答辩 / 比赛评委

需要看到：

- 项目有明确教学痛点。
- 原型已经能跑通核心闭环。
- 后续工程化路径清晰。

## 4. 当前功能范围

当前 `v0.3.0` 原型已支持：

### 4.1 积木式指令编辑

- 左侧指令积木素材。
- 中间指令编辑画布。
- 指令顺序按画布高度从上到下解析。
- 指令下方拼接寄存器、立即数、标签小积木。
- 标签可作为分支或跳转目标。

当前仍未完全实现：

- 真正自由漂浮的小积木。
- 完整自动吸附关系模型。
- Blockly 工作区。

### 4.2 指令支持

基础算术：

- `add`
- `sub`
- `addi`

逻辑运算：

- `and`
- `or`
- `xor`
- `andi`
- `ori`
- `xori`

移位运算：

- `sll`
- `srl`
- `sra`
- `slli`
- `srli`
- `srai`

访存：

- `lw`
- `sw`

条件分支：

- `beq`
- `bne`
- `blt`
- `bge`
- `bltu`
- `bgeu`

跳转：

- `jal`
- `jalr`

教学伪指令：

- `j`
- `bltz`

注意：

- `j` 等价于 `jal x0, label`。
- `bltz` 等价于 `blt rs1, x0, label`。
- `sllv` 不是标准 RISC-V RV32I 指令名，本项目使用 `sll rd, rs1, rs2` 表达变量移位。

### 4.3 机器状态展示

当前已支持：

- PC 显示。
- 寄存器显示。
- 内存显示。
- 十进制 / 二进制 / 十六进制切换。
- 被修改单元高亮。

正在补充：

- 手动初始化寄存器和内存。
- 点击寄存器或内存后显示详细信息。

### 4.4 数据流可视化

当前已支持：

- 取指阶段。
- 读寄存器阶段。
- ALU 运算阶段。
- 访存阶段。
- 写回阶段。
- 分支 / 跳转 PC 更新阶段。

当前动画仍是教学抽象图，不是完整 CPU 微架构仿真。

## 5. 典型使用流程

### 5.1 学生自由构造

1. 从左侧选择指令积木。
2. 拖入编辑区。
3. 将寄存器、立即数、标签拼到指令下方。
4. 查看汇编预览。
5. 单步执行。
6. 观察机器状态和数据流动画。
7. 根据系统提示修正错误。

### 5.2 教师课堂演示

1. 打开示例案例。
2. 切换到演示模式。
3. 单步执行。
4. 讲解每一步数据如何流动。
5. 对比不同指令的数据路径。

### 5.3 大创答辩展示

推荐顺序：

1. 展示问题：汇编指令抽象、状态变化不可见。
2. 展示积木构造：把指令格式变成可拼接结构。
3. 展示单步执行：状态和动画同步变化。
4. 展示扩展性：多类 RV32I 指令已接入。
5. 展示迁移路线：后续接入 Electron + React + TypeScript + Blockly。

## 6. 产品亮点

### 6.1 指令格式具象化

通过积木分区表达 `rd`、`rs1`、`rs2`、`imm`、`label`，降低抽象符号门槛。

### 6.2 状态变化可观察

执行指令后，寄存器、内存、PC 的变化立即呈现，并高亮变化单元。

### 6.3 数据流解释

每条指令都有分阶段动画和解释文本，帮助学生理解“为什么是这个结果”。

### 6.4 支持多进制理解

机器状态支持十进制、二进制、十六进制切换，适合讲解小端序、位运算、移位、无符号比较等概念。

### 6.5 后续可工程化

当前原型已经把指令定义、解析、模拟器和 UI 交互初步分层，后续可迁移到 Blockly 和 Electron 桌面端。

## 7. 当前限制

1. 当前仍是 Web MVP，不是最终桌面端。
2. 拖拽和吸附仍是轻量模拟，不是完整 Blockly 工作区。
3. 数据流动画是教学抽象图，不模拟真实流水线和所有硬件细节。
4. 内存模型简化为整数地址到整数值的映射。
5. 指令集覆盖常用教学子集，不是完整 RV32I。
6. OpenHarmony 页面目前只用于概念展示。

## 9. 待确认产品决策

以下决策已在 2026-05-01 确认：

1. Blockly 卡口机制可以接受，但卡口形状必须尽量定制为四四方方的小矩形缺口，而不是圆弧状缺口。
2. 标签必须作为独立可拖动标签帽，形态为小积木，并与指令集左侧边相接。
3. 桌面端优先 Windows 打包。
4. 需要保存功能，保存文件最好和软件自带样例采用一致格式。
5. 数据流动画迁移阶段暂时不修改视觉方案，先保留当前 SVG 思路。

仍待确认：

1. 当前机器状态初始化是否需要支持批量导入。
2. 内存单位是否按“字”展示，还是要进一步展示“字节”和小端序拆分。
3. 保存文件是否需要支持课堂备注、步骤讲稿、预期结果等扩展字段。

## 10. 推荐默认方案

基于已确认决策，推荐：

- Blockly 第一版优先保证拖拽、连接、排序、解析稳定。
- 在第一版跑通后实现方形卡口 custom renderer，逐步靠近真实积木风格。
- 标签从产品设计上按独立标签帽处理，早期可以数据字段过渡，但视觉应保持左侧小积木贴边效果。
- 机器状态初始化先支持单个寄存器 / 单个内存地址写入。
- 保存文件与内置案例统一格式，便于教师自定义案例。
- 数据流动画先组件化迁移，不大改视觉。
