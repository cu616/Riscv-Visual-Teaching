# 产品说明：RISC-V 指令集可视化教学桌面软件

更新时间：2026-05-14

## 1. 产品定位

本软件面向 RISC-V 初学者、计算机组成原理课程学习者和课堂演示场景，目标是把抽象的汇编指令执行过程转化为可拼接、可观察、可解释的教学体验。

当前阶段的软件是：

```text
教学构想验证原型
```

不是最终可交付的完整桌面软件。当前重点是证明产品构想成立：

- 学生能用积木构造 RISC-V 指令。
- 系统能生成结构化指令和汇编文本。
- 模拟器能单步执行指令。
- 机器状态能同步展示寄存器、内存和 PC。
- 机器状态格动画能解释每条指令为什么产生这样的状态变化。

截至 2026-05-09，产品技术路线确定为：主线回到非 Blockly 自研积木桌面版；Blockly 迁移版保留为技术验证；远期 OpenHarmony 采用 ArkWeb/WebView 先承载，再逐步原生化。该决策是为了保证最终演示外观能符合“指令长条在上、操作数小长方体在下、上下贴边拼接”的真实积木表达。旧文档中提到的独立抽象数据流面板已经暂停，当前动画方向以 `docs/机器状态格动画重构方案.md` 为准。

## 2. 核心教学问题

RISC-V 汇编教学中常见困难包括：

1. 指令格式抽象，初学者难以区分 `rd`、`rs1`、`rs2`、`imm`。
2. 访存指令如 `lw rd, imm(rs1)` 容易把偏移量和寄存器顺序看错。
3. `x0` 恒零寄存器等架构规则不直观。
4. 条件分支和跳转对 PC 的影响不容易观察。
5. 逻辑运算和移位运算需要结合二进制位模式理解。
6. 传统文本汇编缺少即时可视化反馈。

本软件通过“积木构造 + 单步执行 + 机器状态格动画 + 机器状态展示”解决这些问题。

## 3. 目标用户

### 3.1 学生

需要：

- 低门槛理解 RISC-V 指令格式。
- 通过拖拽和观察建立直觉。
- 在错误操作时获得解释。

### 3.2 教师 / 助教

需要：

- 快速加载示例案例。
- 课堂上逐步演示寄存器、内存、PC 的变化。
- 用可视化动画解释指令执行路径。

### 3.3 项目展示 / 教学演示

需要看到：

- 项目有明确教学痛点。
- 原型已经能跑通核心闭环。
- 后续工程化路径清晰。

## 4. 当前功能范围

当前 `v0.3.0` 原型已支持：

### 4.1 积木式指令编辑

- 左侧指令积木素材。
- 中间指令编辑画布。
- 指令顺序按画布高度从上到下解析。
- 指令下方拼接寄存器、立即数、标签小积木。
- 标签可作为分支或跳转目标。

当前仍未完全实现：

- Blockly 工作区。

2026-05-14 设备端展示版补充：

- 小积木支持先放置在工作台空白区域，形成游离小积木，再拖动到对应指令槽位完成拼接。该交互已同步到 OpenHarmony ArkWeb 运行时，符合“先摆放、再拼接”的实体积木使用习惯。
- OpenHarmony 运行时不依赖原生 HTML5 drag/drop，而使用自定义触控/鼠标拖拽层；小积木可拖到删除区删除，也可从已吸附槽位拖出并放回工作台。
- 解析错误不再把所有指令积木统一标红，而是按“第 N 条指令”的错误来源只标记对应积木，并在该积木下方显示具体错误说明。

### 4.2 指令支持

基础算术：

- `add`
- `sub`
- `addi`

逻辑运算：

- `and`
- `or`
- `xor`
- `andi`
- `ori`
- `xori`

移位运算：

- `sll`
- `srl`
- `sra`
- `slli`
- `srli`
- `srai`

访存：

- `lw`
- `sw`

条件分支：

- `beq`
- `bne`
- `blt`
- `bge`
- `bltu`
- `bgeu`

跳转：

- `jal`
- `jalr`

教学伪指令：

- `j`
- `bltz`

注意：

- `j` 等价于 `jal x0, label`。
- `bltz` 等价于 `blt rs1, x0, label`。
- `sllv` 不是标准 RISC-V RV32I 指令名，本项目使用 `sll rd, rs1, rs2` 表达变量移位。

### 4.3 机器状态展示

当前已支持：

- PC 显示。
- 寄存器显示。
- 内存显示。
- 十进制 / 二进制 / 十六进制切换。
- 被修改单元高亮。
- GPIO 模拟外设区：用 `LED-X1`、`RUN`、`ERR` 三个模拟 LED 表示外设反馈。其中 `LED-X1` 与 `x1` 的值绑定，`RUN` 表示当前执行/动画运行状态，`ERR` 表示指令解析错误。

正在补充：

- 手动初始化寄存器和内存。
- 点击寄存器或内存后显示详细信息。

### 4.4 数据流可视化

当前已支持：

- 取指阶段。
- 读寄存器阶段。
- ALU 运算阶段。
- 访存阶段。
- 写回阶段。
- 分支 / 跳转 PC 更新阶段。

当前动画仍是教学抽象图，不是完整 CPU 微架构仿真。

## 5. 典型使用流程

### 5.1 学生自由构造

1. 从左侧选择指令积木。
2. 拖入编辑区。
3. 将寄存器、立即数、标签拼到指令下方。
4. 查看汇编预览。
5. 单步执行。
6. 观察机器状态和数据流动画。
7. 根据系统提示修正错误。

### 5.2 教师课堂演示

1. 打开示例案例。
2. 切换到演示模式。
3. 单步执行。
4. 讲解每一步数据如何流动。
5. 对比不同指令的数据路径。

### 5.3 大创答辩展示

推荐顺序：

1. 展示问题：汇编指令抽象、状态变化不可见。
2. 展示积木构造：把指令格式变成可拼接结构。
3. 展示单步执行：状态和动画同步变化。
4. 展示扩展性：多类 RV32I 指令已接入。
5. 展示迁移路线：后续接入 Electron + React + TypeScript + Blockly。

## 6. 产品亮点

### 6.1 指令格式具象化

通过积木分区表达 `rd`、`rs1`、`rs2`、`imm`、`label`，降低抽象符号门槛。

### 6.2 状态变化可观察

执行指令后，寄存器、内存、PC 的变化立即呈现，并高亮变化单元。

### 6.3 数据流解释

每条指令都有分阶段动画和解释文本，帮助学生理解“为什么是这个结果”。

### 6.4 支持多进制理解

机器状态支持十进制、二进制、十六进制切换，适合讲解小端序、位运算、移位、无符号比较等概念。

### 6.5 后续可工程化

当前原型已经把指令定义、解析、模拟器和 UI 交互初步分层，后续可迁移到 Blockly 和 Electron 桌面端。

### 6.6 OpenHarmony/RISC-V 设备端展示增强

2026-05-14 设备端展示版新增 `OpenHarmony/RISC-V 实机路线` 页面，用于把当前软件样机、OpenHarmony 运行平台和后续实体智能积木路线放在同一张图中说明。

该页面强调以下边界：

- 当前已经完成的是 OpenHarmony/香橙派 RV2 上的 ArkWeb 应用运行，以及 RISC-V 指令教学模拟器。
- 当前 GPIO 与 LED 均为软件模拟硬件反馈，不宣称已经真实接入外部 GPIO、星闪设备或软总线设备。
- 页面中的外部 LED 模块位于主控模块下方，表示后续可由主控通过 GPIO、软总线或无线对端设备驱动的外设反馈。
- 页面支持比例调整和上下滚动，便于在 1920x1080 触控屏上纵观全局。

## 7. 当前限制

1. 当前仍是 Web MVP，不是最终桌面端。
2. 拖拽和吸附仍是轻量模拟，不是完整 Blockly 工作区。
3. 数据流动画是教学抽象图，不模拟真实流水线和所有硬件细节。
4. 内存模型简化为整数地址到整数值的映射。
5. 指令集覆盖常用教学子集，不是完整 RV32I。
6. OpenHarmony 页面目前只用于概念展示。

2026-05-14 更新：OpenHarmony 页面已从单纯概念展示调整为“当前已完成 + 后续接入路线”的设备端展示页。它仍不代表真实软总线或外部 LED 硬件已完成接入，而是用于说明从当前样机扩展到实体智能积木系统的技术路线。

## 8. 下一阶段产品方向

### 8.1 复合指令与临时寄存器约定

2026-05-11 补充：复合指令允许像函数/伪指令一样展开为多条基础指令。当前复合指令不应隐藏使用普通输入输出寄存器作为中间变量；未来若需要临时计算，统一按 RISC-V ABI 使用 `x5-x7`、`x28-x31`，即 `t0-t6` 临时寄存器。

界面要求：
- 机器状态区显示全部 32 个寄存器。
- `x5/t0`、`x6/t1`、`x7/t2`、`x28/t3`、`x29/t4`、`x30/t5`、`x31/t6` 的临时寄存器说明只在鼠标悬停或点击对应寄存器时显示，避免常态界面干扰学生观察。
- 复合指令执行解释中若涉及这些寄存器，需要说明其为内部临时值，不作为显式输入或输出接口。

下一阶段建议进入：

```text
Blockly 迁移与正式桌面原型阶段
```

核心目标：

- 用 Blockly 替换当前自研轻量拖拽。

- 保留当前模拟器和教学解释逻辑。

## 9. 待确认产品决策

以下决策已在 2026-05-01 确认：

1. Blockly 卡口机制可以接受，但卡口形状必须尽量定制为四四方方的小矩形缺口，而不是圆弧状缺口。
2. 标签必须作为独立可拖动标签帽，形态为小积木，并与指令集左侧边相接。
3. 桌面端优先 Windows 打包。
4. 需要保存功能，保存文件最好和软件自带样例采用一致格式。
5. 数据流动画迁移阶段暂时不修改视觉方案，先保留当前 SVG 思路。

仍待确认：

1. 当前机器状态初始化是否需要支持批量导入。
2. 内存单位是否按“字”展示，还是要进一步展示“字节”和小端序拆分。
3. 保存文件是否需要支持课堂备注、步骤讲稿、预期结果等扩展字段。

## 10. 推荐默认方案

基于已确认决策，推荐：

- Blockly 第一版优先保证拖拽、连接、排序、解析稳定。
- 在第一版跑通后实现方形卡口 custom renderer，逐步靠近真实积木风格。
- 标签从产品设计上按独立标签帽处理，早期可以数据字段过渡，但视觉应保持左侧小积木贴边效果。
- 机器状态初始化先支持单个寄存器 / 单个内存地址写入。
- 保存文件与内置案例统一格式，便于教师自定义案例。
- 数据流动画先组件化迁移，不大改视觉。
