# AI 协作沟通经验

更新时间：2026-05-09

> 状态说明：本文是跨阶段沟通经验记录，不是最新开发计划。第 6 节和第 10 节保留了早期“右侧固定数据流”“Blockly 迁移”的阶段性判断；当前主线已更新为 `app/` 非 Blockly 自研积木，右侧为可收合辅助栏，数据流动画改为机器状态格动画。若与 `docs/文档状态与路线索引.md` 冲突，以后者为准。

本文用于帮助后续接手本项目的 AI 或开发者理解本轮沟通经验，减少重复误解。

## 1. 用户最关心的不是“能跑”，而是“是否符合教学产品想象”

本项目虽然是软件开发任务，但用户持续强调的是教学演示体验。

判断实现是否合格时，不能只看：

- 功能是否存在
- 按钮是否可点
- 数据是否能执行

还要看：

- 初学者是否一眼能理解
- 视觉是否像真实教学工具
- 演示时是否清楚
- 是否符合“可视化教学”的直觉

## 2. “积木拼接”不是表单，也不是槽位控件

这是沟通中最重要的经验。

用户说的积木拼接，是指真实积木的视觉逻辑：

```text
上方：一条指令长条积木
下方：若干独立小长方形积木直接贴边拼接
```

错误理解包括：

- 把 `rd/rs1/imm` 做成表单字段
- 把小积木嵌入大积木内部
- 用一个浅色框把所有小积木包起来
- 让大积木主体里出现“槽口”

正确方向：

- 指令主体内部只显示指令名和必要序号
- 操作数小积木应在主体下方
- 小积木与大积木通过边相邻形成拼接感
- 空接口最好只在拖拽时作为提示显示

## 3. 用户希望交互像真实编辑，而不是线性堆栈

用户明确指出：

- 写代码不是写完第一行才能写第二行
- 应允许复制、粘贴、移动代码位置
- 指令顺序应按画布中从上到下的高度判断

因此：

- 不要把程序简单当数组队列渲染
- 指令块应能自由移动
- 解析时按 `y` 坐标排序
- 示例案例加载后应自动排布整齐

## 4. 标签帽不应常驻显示

标签帽如果一直显示，会让界面冗余、丑。

正确交互：

- 默认隐藏标签帽
- 拖动标签小积木时显示可贴区域
- 指令已有标签时显示标签帽

## 5. 左侧素材区要精简

不要堆很多寄存器、立即数和标签预设。

用户更希望：

- 寄存器通过下拉选择
- 立即数通过输入框填写
- 标签名通过输入框填写
- 素材区生成当前选择的一个小积木

这样不会占据过多 UI 高度，也更适合演示。

## 6. 机器状态与数据流必须始终可见（历史经验，已修订）

用户需要在演示时持续观察：

- 指令编辑区
- 机器状态
- 数据流动画

当时右侧布局建议为：

```text
上：机器状态
下：数据流可视化
```

当前修订：右侧不再固定为“上机器状态、下数据流动画”。现在采用可收合辅助栏，机器、代码、说明作为页签；动画表达式挂载到机器页顶部 `state-animation-dock`，执行时自动切到机器页。旧数据流面板已暂停，后续以机器状态格动画为准。

## 7. 用户会用具体反例纠正 AI

本轮沟通中，用户多次用“不是这样，而是……”纠正。

后续 AI 应该：

1. 认真吸收最新一轮反馈。
2. 不要坚持旧实现。
3. 对视觉/交互类任务，优先修改现有原型让用户能看见差异。
4. 遇到“最终演示效果不清晰”时及时问用户决策。

## 8. 推荐后续提问方式

当不确定积木视觉时，不要直接大改，先问：

```text
这个设计更接近 A 还是 B？
A：Scratch / Blockly 式卡扣
B：真实长方体积木上下贴边
C：电路模块接口吸附
```

当不确定布局时，先问：

```text
你希望右侧是固定宽度，还是随屏幕自适应？
```

当不确定是否进入正式工程时，先问：

```text
当前是否继续打磨无依赖 Web 原型，还是开始迁移 Electron + React + Blockly？
```

## 9. 当前阶段判断

截至 v0.2 开发前，本项目处于：

```text
无依赖 Web MVP → 积木交互与教学演示强化
```

还不是正式 Electron 桌面软件，也不是真 Blockly。

后续 AI 不应误以为当前已经完成最终产品。

## 10. Blockly 迁移最新决策（历史经验，已降级）

用户已确认：

- 可以进入 Blockly 迁移思路，但不能接受默认圆弧状少儿编程缺口。
- 卡口应尽量定制为四四方方的小矩形缺口，与当前“真实积木”审美一致。
- 标签必须作为独立可拖动标签帽，最好做成小积木形状，并贴在指令 block 左侧边。
- 桌面端优先 Windows 打包。
- 需要保存功能，保存文件最好和软件自带样例使用同一格式。
- 数据流动画迁移阶段暂时不修改视觉方案，先保留当前 SVG 思路。

当前修订：Blockly 迁移版已经降级为技术验证和工程参考。后续 AI 不要把“继续迁移 Blockly”当成默认任务；主线新功能应优先在 `app/` 非 Blockly 自研积木中完成。Blockly 相关内容仅在明确维护 `desktop/` 验证版时适用。
