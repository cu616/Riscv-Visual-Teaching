# 长期任务 v0.4：案例工程化与初始状态闭环

日期：2026-05-04

## 1. 任务目标

本轮长期任务不做零散修补，而是把非 Blockly 主线推进到“可保存一个完整教学案例”的状态。

目标闭环：

```text
编辑指令和自由小积木
→ 配置机器初始寄存器/内存
→ 编写教学备注
→ 保存 .riscvteach.json
→ 清空后导入
→ 恢复程序、自由小积木、显示进制、初始状态、备注
→ 自动检查能发现主结构和静态资源问题
```

## 2. 工程边界

本轮仍遵守以下边界：

1. 不迁移回 Blockly。
2. 不引入新依赖。
3. 不修 Electron 原生 exe，继续把 Edge / Chrome 应用窗口作为稳定入口。
4. 不把状态规则散落在 DOM 事件里，优先新增纯模型并测试。
5. 每个阶段都必须通过：

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run smoke
```

## 3. 阶段拆解

### 阶段 A：机器初始状态模型

产物：

- `app/src/machine-state.js`
- `app/test-core.mjs` 中的纯函数测试

职责：

- 归一化 `initialState.registers`
- 归一化 `initialState.memory`
- 根据初始状态创建可执行机器状态
- 写入或清除单个初始值

验收：

- `x0` 仍保持恒零。
- 字符串数字可以归一化为整数。
- 非法寄存器、非法地址、非整数值会被拒绝或过滤。

### 阶段 B：初始状态 UI 接入

产物：

- `app/src/app.js`
- `app/styles.css`

职责：

- 右侧“机器状态初始化”控件真正可用。
- 写入寄存器或内存初始值后，执行状态立即重置。
- 寄存器/内存格显示哪些值来自初始状态。
- 点击寄存器/内存格可查看当前值和初始值。

验收：

- 设置 `x1 = 16` 后，单步执行前寄存器视图显示 `x1` 为 16。
- 设置内存地址 `16 = 99` 后，保存导入仍恢复。

### 阶段 C：教学备注保存导入

产物：

- `app/index.html`
- `app/src/app.js`
- `app/styles.css`
- `app/src/case-format.js`

职责：

- 页面提供教学备注输入区。
- 保存案例时写入 `notes`。
- 导入案例时恢复 `notes`。

验收：

- 保存 JSON 包含 `notes`。
- 导入后备注内容恢复。

### 阶段 D：自动验收增强

产物：

- `app/smoke-http.mjs`

职责：

- 烟测覆盖初始状态控件和备注控件的关键 DOM 锚点。

验收：

- 首页缺少关键控件时 `npm.cmd run smoke` 失败。

## 4. 明早排查方式

如果明早出现问题，优先按这个顺序反馈：

```text
问题类型：
复现步骤：
看到的现象：
期望效果：
保存文件是否包含 initialState / notes：
```

对应定位：

| 现象 | 优先查看 |
| --- | --- |
| 初始状态保存不对 | `app/src/machine-state.js`、`app/src/case-format.js` |
| 写入后右侧状态不刷新 | `app/src/app.js` 的 state editor 绑定 |
| 导入后状态没恢复 | `app/src/app.js` 的 importProgramFile |
| 备注不保存 | `app/index.html`、`app/src/app.js`、`app/src/case-format.js` |
| 自动验收失败 | `app/smoke-http.mjs` |
