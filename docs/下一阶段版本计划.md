# 下一阶段版本计划

更新时间：2026-05-01

状态：`v0.3.0` 已在 v0.2 交互基础上扩展常用教学指令，并增强部分数据流动画文案；仍保留“完全自由小积木与自动吸附”作为后续重点。

## 1. 当前所处阶段

当前项目处于 **无依赖 Web MVP 原型阶段**。

目前已经完成了基本链路：

```text
指令积木拖入编辑区
→ 操作数小积木拼接
→ 结构化指令解析
→ 汇编预览
→ 教学模拟执行
→ 机器状态显示
→ 数据流可视化
→ 执行日志与教学解释
```

但是当前版本仍是“原型验证”，还不是最终产品形态。下一阶段的核心任务不是继续堆功能，而是把 **积木拼接体验、布局可用性、数据流演示质量、工程结构** 做扎实。

## 2. 下一阶段版本目标

当前下一阶段建议命名为：

```text
v0.4 积木吸附与工程化强化版
```

目标是让软件从“能演示功能”提升到“能让用户清楚理解并顺畅操作”。

## 3. v0.2 必须完成的内容

### 3.1 积木拼接交互重构

这是下一阶段最重要的内容。

当前问题：

- 指令积木虽然已经是长条形，但仍然缺少真实积木吸附感。
- 小积木还不是真正自由的独立积木。
- 小积木与指令积木之间的连接关系仍然偏 UI 模拟。

下一阶段要求：

1. 小积木应作为独立矩形块存在。
2. 小积木可在编辑画布中自由拖动。
3. 小积木靠近指令积木下边缘的对应位置时自动吸附。
4. 小积木未吸附时应停留在画布中，而不是消失或强制回到素材区。
5. 已吸附的小积木可以再次拖出。
6. 指令积木主体内部不得出现操作数槽口。
7. 指令积木外观应保持：

```text
上方：一条长方形指令主体
下方：若干独立小长方形操作数积木直接贴边拼接
```

8. 指令执行解析应根据“吸附关系”读取字段，而不是依赖隐藏表单。

验收标准：

- 拖动一个 `addi` 指令到画布后，能拖动 `rd`、`rs1`、`imm` 小积木贴到其下方。
- 拖错类型时有明确提示。
- 拖走小积木后，该字段变为空，汇编预览同步报错。
- 用户能直观看出“小积木是拼在大积木下面”，而不是填进大积木内部。

### 3.2 指令块排序与程序顺序优化

当前状态：

- 指令顺序按画布中指令积木的高度从上到下解析。

下一阶段要求：

1. 保留按高度解析的规则。
2. 增加视觉上的排序辅助线。
3. 拖动指令时显示当前将插入到哪一行。
4. 支持对齐到网格，减少拖动后错位。
5. 示例案例加载后应自动排列整齐。

验收标准：

- 用户能通过拖动改变指令执行顺序。
- 汇编预览顺序与画布从上到下的顺序一致。
- 示例案例加载后不重叠、不散乱。

### 3.3 左侧素材区优化

当前状态：

- 左侧素材区已经精简为寄存器、立即数、标签名输入。

下一阶段要求：

1. 保留精简输入，不恢复大量预设小积木。
2. 点击“生成”或拖动时生成一个真实可拖动小积木。
3. 小积木应显示清晰类型：
   - 寄存器：浅蓝
   - 立即数 / 地址偏移：浅黄
   - 标签：浅绿
4. 标签名允许用户自定义。
5. 立即数和地址偏移允许键盘输入。
6. 素材区应固定高度，不影响编辑区视野。

验收标准：

- 用户能快速生成 `x1`、`#8`、`loop` 等小积木。
- 小积木可以拖到画布中或吸附到指令积木下方。

### 3.4 机器状态与数据流可视化布局固定

当前状态：

- 机器状态已放在右侧上方。
- 数据流可视化已放在右侧下方。

下一阶段要求：

1. 右侧栏保持：

```text
上：机器状态
下：数据流可视化
```

2. 两个区域宽度一致。
3. 用户调整中间编辑区宽度时，右侧区域仍可读。
4. 机器状态不应被挤到底部。
5. 寄存器和内存变化要保持明显高亮。

验收标准：

- 在常见 1080p 屏幕下，用户能同时看到：
  - 指令编辑区
  - 机器状态
  - 数据流动画

### 3.5 数据流动画教学性增强

当前问题：

- 当前数据流动画仍偏简单高亮。
- 对不同指令的数据路径差异表达还不够强。

下一阶段要求：

1. 每类指令使用不同动画脚本：
   - `add/sub`：寄存器 → ALU → 写回寄存器
   - `addi`：寄存器 + 立即数 → ALU → 写回寄存器
   - `lw`：寄存器 + 偏移 → ALU 算地址 → 内存读取 → 写回寄存器
   - `sw`：寄存器 + 偏移 → ALU 算地址 → 内存写入
   - `beq`：两个寄存器比较 → 判断是否修改 PC
2. 动画应分阶段播放，而不是一次性全亮。
3. 每个阶段配套一句教学解释。
4. 当前执行指令应在画布中同步高亮。

验收标准：

- 学生能通过动画看出 `lw` 和 `sw` 的区别。
- 学生能通过动画看出 `add` 和 `addi` 的区别。
- 分支跳转时 PC 变化清楚可见。

### 3.6 示例案例与演示模式

当前状态：

- 已有示例案例加载功能。

下一阶段要求：

1. 示例案例加载后应自动生成清晰排列的积木程序。
2. 每个案例应对应一个明确教学点：
   - 立即数赋值
   - 两数相加
   - 内存读写
   - 条件分支
3. 添加“演示模式”开关：
   - 隐藏 JSON 预览
   - 放大积木和数据流
   - 保留汇编和教学解释

验收标准：

- 答辩时能一键加载案例并顺畅演示。
- 不需要现场从零拼所有积木。

## 4. v0.3 已完成的夜间扩展

本轮已经谨慎扩展常用教学指令：

- 逻辑：`and`、`or`、`xor`、`andi`、`ori`、`xori`
- 移位：`sll`、`srl`、`sra`、`slli`、`srli`、`srai`
- 分支：`bne`、`blt`、`bge`、`bltu`、`bgeu`
- 跳转：`jal`、`jalr`
- 教学伪指令：`j`、`bltz`

已同步完成：

- 指令定义
- 默认积木生成
- 汇编格式化
- 教学解释
- 模拟执行语义
- 数据流动画分类文案
- 核心测试

格式核对重点：

- `lw rd, imm(rs1)`
- `sw rs2, imm(rs1)`
- `jal rd, label`
- `jalr rd, imm(rs1)`
- `sll/srl/sra rd, rs1, rs2`
- `slli/srli/srai rd, rs1, shamt`
- `beq/bne/blt/bge/bltu/bgeu rs1, rs2, label`

`sllv` 未作为标准 RISC-V 指令加入；如需表达变量移位，使用 `sll rd, rs1, rs2`。`bltz` 仅作为教学伪指令，等价于 `blt rs1, x0, label`。

## 5. 近期不建议继续扩展的内容

短期不要急着做以下内容：

1. 完整 RV32I 指令集。
2. 真实 CPU 流水线。
3. 真实 OpenHarmony 通信。
4. 用户账号系统。
5. 数据库。
6. 复杂课程系统。
7. 语音讲解。
8. CV 实体积木识别。

原因：

- 当前核心交互还没定型。
- 过早扩展会增加维护成本。
- 大创演示首先需要一个稳定、清楚、可讲解的最小闭环。

## 6. 下一阶段之后仍需完成的内容

这些不是 v0.2 必须完成，但后续必须规划。

### 5.1 正式工程迁移

当前是无依赖 Web MVP。后续需要迁移到正式技术栈：

- Electron
- React
- TypeScript
- Vite
- Blockly

迁移要求：

1. 保留当前解析器和模拟器思想。
2. 将 UI 组件拆分为独立 React 组件。
3. 将指令类型改为 TypeScript 类型。
4. 将积木拼接逻辑逐步替换为 Blockly 或自定义积木系统。

### 5.2 Blockly 或自研积木系统决策

后续需要决策：

```text
是使用 Blockly 深度定制，还是自研轻量积木拼接系统？
```

Blockly 优点：

- 拖拽成熟
- 吸附、排序、连接规则已有基础
- 适合快速稳定实现

Blockly 风险：

- 默认视觉偏少儿编程
- 深度定制成本可能较高
- 要实现 RISC-V 教学语义仍需大量自定义

自研优点：

- 视觉完全可控
- 更容易做成真实积木风格

自研风险：

- 拖拽、吸附、排序、连接规则都要自己维护
- 工程复杂度高

### 5.3 测试体系完善

后续需要增加：

- UI 交互测试
- 示例案例测试
- 每条指令执行测试
- 标签跳转测试
- 拖拽吸附测试

建议引入 Playwright 或同类浏览器自动化测试。

### 5.4 桌面端打包

后续需要完成：

- Electron 桌面壳
- Windows 打包
- 一键安装或免安装运行包
- 图标与启动页

## 7. v0.4 推荐开发顺序

建议按以下顺序推进：

1. 重构积木数据模型：
   - 指令块
   - 操作数块
   - 吸附关系
2. 实现操作数小积木自由拖动。
3. 实现小积木吸附到指令下方。
4. 改造解析器，从吸附关系生成结构化指令。
5. 优化画布排序与对齐。
6. 强化右侧机器状态和数据流布局。
7. 优化每类指令动画脚本。
8. 修复示例案例布局。
9. 增加演示模式。
10. 补充 UI 测试。

## 8. v0.4 完成标准

当满足以下条件时，可以认为 v0.2 完成：

- 用户能用真实拼接感的积木构造至少 4 类指令。
- 指令顺序可通过拖动改变。
- 示例案例可一键加载并演示。
- 机器状态和数据流动画始终可见。
- 每条指令的执行过程有清晰动画和解释。
- 核心测试全部通过。
- 可以用于组会或阶段答辩演示。
