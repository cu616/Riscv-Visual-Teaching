### 1.2 产品定位

- 面向谁使用
- 解决什么问题
- 与传统教学软件的区别

### 1.3 核心教学目标

- 帮助初学者理解基础 RISC-V 指令
- 帮助用户理解“指令如何被执行”
- 帮助用户看到寄存器、ALU、内存之间的数据流动
- 用可视化方式建立对底层计算机结构的直觉

### 1.4 产品核心理念

- 具身认知
- 拖拽式编程
- 指令执行透明化
- 数据流可视化
- 教学优先，工程复杂度适中

### 1.5 产品边界

- 不实现完整 CPU
- 不追求完整 RISC-V 指令集
- 不优先处理 CV 实体识别
- OpenHarmony 仅做概念可视化，不做真实分布式系统

## 9. Blockly 使用方案

### 9.1 为什么选 Blockly

- 可视化拖拽成熟
- 适合积木式编程
- 易于扩展
- 社区资源较多

### 9.2 Blockly 在本项目中的角色

- 作为拖拽积木编辑器
- 负责模块拼接和规则约束
- 不负责底层指令执行

### 9.3 需要自定义哪些 Block

- 操作类型 block
- 寄存器 block
- 立即数 block
- 内存地址 block
- 分支目标 block

### 9.4 Block 的字段设计

- 每个 block 有哪些参数
- 是否可下拉选择
- 是否可文本输入
- 是否需要颜色区分

### 9.5 Block 之间的连接规则

- 哪些 block 可以连接
- 哪些组合非法
- 如何在 Blockly 中设置约束

### 9.6 从 Blockly 到指令结构的转换

- 如何读取 block 树
- 如何生成内部 JSON 表示
- 如何生成汇编文本表示

### 9.7 Blockly 的二次开发点

- 自定义工具箱
- 自定义积木外观
- 自定义校验规则
- 与桌面应用框架的集成

### 9.8 Blockly 的局限与规避方案

- 默认逻辑偏向通用编程
- 需要自定义很多教学语义
- 如何避免界面太像少儿编程

### 9.9 当前迁移阶段结论

当前原型已经证明了教学闭环，但自研拖拽继续深入会带来较高工程复杂度。因此下一阶段建议进入 Blockly 迁移阶段。

迁移原则：

- 当前 `app/` 无依赖 MVP 保留为答辩备用版本。
- 新建 `desktop/` 正式工程承载 Electron + React + TypeScript + Vite + Blockly。
- Blockly 负责拖拽、吸附、连接规则和工作区保存加载。
- RISC-V 指令执行仍由独立模拟器完成。
- Blockly 解析层只负责生成结构化 `Instruction[]`，不直接执行指令。

阶段目标：

1. 先搭建桌面工程空壳。
2. 再抽离现有指令定义和模拟器核心。
3. 再接入最小 Blockly 工作区。
4. 最后扩展到当前 v0.3 已支持的指令集。

详细迁移方案见：


当前产品说明见：

