# RISC-V 可视化教学软件演示脚本

更新时间：2026-05-01

## 1. 演示定位

当前软件是大创比赛草案演示程序 / 构想验证原型，重点不是证明它已经达到可交付桌面软件标准，而是证明团队的教学设计思路可运行、可讲解、可继续工程化。

核心话术：

```text
我们希望把 RISC-V 指令从抽象文本变成可拼接、可观察、可单步解释的教学对象。
学生先用积木构造指令，再观察汇编、寄存器、内存、PC 和数据流动画如何同步变化。
```

## 2. 推荐演示顺序

### 2.1 打开软件

运行：

```powershell
npm.cmd start
```

或双击：

```text
启动RISC-V可视化教学软件.bat
```

浏览器打开：

```text
http://localhost:4173
```

讲解点：

- 左侧是指令大积木和操作数小积木素材。
- 中间是指令编辑区，指令顺序按积木高度从上到下解析。
- 右侧上方是机器状态，右侧下方是数据流可视化。
- 下方保留汇编预览和执行日志，用于讲解与调试。

### 2.2 演示立即数赋值

选择案例：`立即数赋值`

执行：

1. 点击“加载案例”。
2. 切回工作台。
3. 单步执行。

观察：

- `addi x1, x0, 5`
- `x0` 恒为 0。
- `x1` 变为 5。
- ALU 阶段显示寄存器值与立即数相加。

可补充提问：

```text
如果把 rd 改成 x0，会发生什么？
```

答案：

```text
x0 是 RISC-V 的恒零寄存器，写入会被忽略。软件会给出提示。
```

### 2.3 演示内存读写

选择案例：`内存读写`

观察：

- `sw rs2, imm(rs1)` 把寄存器值写入内存。
- `lw rd, imm(rs1)` 从内存读回寄存器。
- 地址由 `rs1 + imm` 得到。

强调：

```text
这里的 lw 可视化顺序是 rd、imm、rs1，对应汇编格式 lw rd, imm(rs1)。
之前容易把偏移量放错位置，因此后续扩展指令必须严格核对格式。
```

### 2.4 演示二进制与逻辑运算

选择案例：`按位逻辑与移位`

执行前先把机器状态切到“二进制”。

观察：

- `and` 展示按位保留。
- `or` 展示按位设置。
- `xor` 展示按位翻转差异。
- `slli` 展示位向左移动。

讲解点：

```text
逻辑运算不是普通十进制加减，而是每一位单独进入 ALU。
因此二进制显示能帮助学生理解掩码、位设置和位移动。
```

### 2.5 演示立即数掩码

选择案例：`掩码与位设置`

执行前建议保持“二进制”显示。

观察：

- `andi` 用掩码保留部分低位。
- `ori` 设置某个标志位。
- `xori` 翻转若干位。

讲解点：

```text
这一组适合说明：立即数不只可以参与加法，也可以作为掩码参与位运算。
```

### 2.6 演示移位差异

选择案例：`三类移位对比`

观察：

- `sll` 左移，低位补 0。
- `srl` 逻辑右移，高位补 0。
- `sra` 算术右移，高位补符号位。
- `slli/srli/srai` 的移位量来自 shamt。

讲解点：

```text
RISC-V RV32 中变量移位用 sll/srl/sra，移位量来自 rs2 的低 5 位。
sllv 是 MIPS 风格名称，不作为本项目的标准 RISC-V 指令展示。
```

### 2.7 演示条件分支

选择案例：`条件分支`

观察：

- `beq rs1, rs2, label`
- 当条件成立时，PC 直接跳到目标标签。
- 被跳过的指令不会执行。

讲解点：

```text
这里绿色标签不是注释，而是跳转目标。分支指令引用标签，模拟器解析为目标指令序号。
```

### 2.8 演示有符号与无符号比较

选择案例：`有符号与无符号分支`

观察：

- `blt x1, x2, label` 把 `-1` 当作有符号数，小于 `1`。
- `bgeu x1, x2, label` 把同一个位模式当作无符号数，`0xFFFFFFFF` 大于等于 `1`。

讲解点：

```text
同样的二进制位模式，在有符号和无符号分支里含义不同。
这也是为什么机器状态支持二进制/十六进制显示。
```

### 2.9 演示无条件跳转

选择案例：`无条件跳转`

观察：

- `jal x0, target`
- PC 直接跳到 `target`。
- 因为 rd 是 `x0`，返回地址写入被忽略，所以形成无条件跳转效果。

讲解点：

```text
RISC-V 标准里常用 jal rd, label。若 rd 用 x0，就可以作为无条件跳转。
本项目也提供 j label 作为教学伪指令，但会标注它不是 RV32I 基础独立指令。
```

### 2.10 演示 JAL 保存返回位置

选择案例：`JAL 保存返回位置`

观察：

- `jal x1, target`
- PC 跳到目标标签。
- `x1` 保存下一条指令位置，便于解释“链接”的含义。

讲解点：

```text
如果 rd 是 x0，就是不保存返回位置的无条件跳转；如果 rd 是 x1，则能看到返回位置被写入。
```

### 2.11 演示教学伪指令

选择案例：`教学伪指令`

观察：

- `bltz rs1, label` 表达“小于 0 时跳转”。
- `j label` 表达无条件跳转。

讲解点：

```text
这两个是为了降低教学门槛而提供的伪指令。实际解释时要说明：
bltz 可等价理解为 blt rs1, x0, label；
j 可等价理解为 jal x0, label。
```

## 3. 演示模式说明

“演示模式”用于答辩或课堂展示：

- 隐藏 JSON 预览，减少干扰。
- 放大积木和数据流区域。
- 保留汇编、机器状态、数据流动画和教学解释。

注意：

```text
演示模式不是另一套执行逻辑，只是让展示更聚焦。
```

## 4. 当前限制如何解释

可以坦诚说明：

- 当前仍是无依赖 Web MVP，不是最终 Electron 桌面端。
- 小积木已经有独立矩形拼接视觉，但完整自由漂浮和自动吸附还在后续阶段。
- 数据流动画目前是教学抽象图，不是真实 CPU 微架构仿真。
- OpenHarmony 页面目前只展示未来多端协同概念，不接入真实系统通信。

推荐话术：

```text
本阶段我们优先验证教学闭环：积木构造、汇编生成、状态变化、数据流解释。
后续工程化会迁移到更正式的桌面技术栈，并重点增强积木吸附系统与数据流表现。
```

## 5. 容易被问到的问题

### Q1：为什么 `addi x0, x0, 1` 后 x0 还是 0？

因为 `x0` 是 RISC-V 架构规定的恒零寄存器，任何写入都会被忽略。

### Q2：为什么有 `bltz` 和 `j`，它们是标准指令吗？

在本项目中它们是教学伪指令：

- `bltz rs1, label` 等价于 `blt rs1, x0, label`
- `j label` 等价于 `jal x0, label`

这样做是为了降低初学者理解门槛，同时在文档中明确区分标准指令和伪指令。

### Q3：为什么没有加入完整 RV32I？

当前重点是比赛草案演示和教学闭环验证。完整指令集会增加 UI 和测试成本，后续应在交互稳定后分批加入。

### Q4：为什么 `sllv` 没有作为标准指令加入？

`sllv` 是 MIPS 风格命名。标准 RISC-V RV32I 中变量移位使用：

```text
sll rd, rs1, rs2
```

其中 `rs2` 的低 5 位作为移位量。
