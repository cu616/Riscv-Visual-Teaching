# 2026-05-09 UI 界面与功能改动总结

更新时间：2026-05-09

关联提交：

```text
c1dad1f feat: refine state animation UI and align docs
```

本文专门记录本次非 Blockly 自研积木主线在 UI 界面、交互功能和教学动画上的实际改动，便于后续验收、问题反馈和 AI 接手。

## 1. 总体方向

本轮改动继续坚持当前主线：

```text
app/ 非 Blockly 自研积木
→ 右侧可收合辅助栏
→ 机器状态格动画
→ OpenHarmony rawfile 同步
```

旧的独立抽象数据流面板不再作为当前主线展示重点。执行动画改为围绕寄存器、内存、PC 和表达式卡片进行解释。

## 2. 工作区布局调整

### 2.1 编辑区成为底层画布

指令编辑区现在更接近“底层画布”：

- 左侧指令/操作数素材栏悬浮在画布上方。
- 右侧辅助栏悬浮在画布上方，可展开和收合。
- 底部日志区悬浮在画布上方。
- 指令积木区不再被传统三栏布局硬切割。

这使得用户拼接大量积木时，画布仍然是主要工作区域。

### 2.2 左侧素材栏可调宽度

左侧素材栏支持横向调整宽度。调整后：

- 指令编辑画布的可视范围同步变化。
- 积木拖拽边界会避开素材栏。
- 积木不会被素材栏右边缘遮住，减少视觉上“被压住”的情况。

### 2.3 右侧辅助栏可调宽度

右侧辅助栏支持横向调整宽度。辅助栏当前包含：

```text
机器 / 代码 / 说明
```

三类页签，不再强制把机器状态、代码预览、教学说明同时铺在页面上。

### 2.4 底部日志区可调高度

底部执行日志作为浮动区域存在，不再把编辑区整体向上挤压。它可通过底部拖拽条调整高度。

## 3. 辅助栏内容调整

### 3.1 机器状态页

机器状态页现在承担执行观察的主要职责：

- 寄存器格。
- 内存格。
- 进制切换。
- 初始状态写入/清除。
- 当前动画表达式展示。
- OpenHarmony 展示的临时占位。

### 3.2 代码页

代码页保留汇编预览，删去了汇编预览下方的 JSON 代码部分。

原因：

- JSON 对课堂演示帮助较小。
- 放在底部时用户很难看到。
- 代码页应更专注于当前程序的汇编文本。

### 3.3 说明页

教学说明被收纳到辅助栏页签中，需要时再打开，避免长期占用拼接空间。

## 4. PC 显示调整

旧版本中，PC 在机器状态栏里占据一整行大卡片。

本轮改为：

```text
顶部执行进度条旁显示：PC <value>
```

这样做的原因：

- PC 信息很重要，但不需要占用寄存器/内存区上方的大面积空间。
- 执行进度和 PC 本身都属于运行控制信息，放在同一区域更自然。
- 执行到 PC 阶段时只做小高亮，不再让机器状态页出现过大的 PC 卡片。

## 5. 积木编辑交互增强

### 5.1 Ctrl 多选

当前支持使用 Ctrl 辅助选择积木：

- Ctrl + 点击可多选指令积木。
- Ctrl + 拖拽空白区域可框选多个对象。
- 选中多个对象后可批量拖拽。

该功能用于解决程序块较多时逐个移动效率低的问题。

### 5.2 删除能力补齐

拖出的自由小积木现在不再只能移动，已补齐删除路径：

- 支持选中后按 Delete / Backspace 删除。
- 支持多选后批量删除。
- 右下角垃圾桶删除交互已作为当前方向记录，后续仍可继续打磨视觉和触发范围。

### 5.3 空白区域拖拽平移画布

当积木位置较多或画布超出可视范围时，可以在空白区域拖拽画布，调整可视位置。

这是为了解决：

- 积木放远后不好找。
- 画布不能上下移动导致很难重新整理布局。
- 拼接区需要像工作台一样能被拖动查看。

### 5.4 拖拽提示弱化

“把右侧积木拖到这里可上下拖动排序”这类常驻提示已被弱化。现在倾向于：

- 平时不显示占位提示。
- 拖拽指令时才出现释放提示。
- 让界面在非拖拽状态下更干净。

## 6. 执行动画重构

### 6.1 新增动画模块

新增文件：

```text
app/src/state-animation.js
```

职责：

- 根据当前执行结果生成动画阶段。
- 高亮读取的寄存器/内存。
- 高亮写回的寄存器/内存。
- 展示当前运算表达式。
- 管理动画生命周期和清理。

OpenHarmony rawfile 同步路径：

```text
openharmony-port/entry/src/main/resources/rawfile/app/src/state-animation.js
```

### 6.2 表达式卡片

动画不再只靠两个蓝色小卡片靠近来暗示“发生了运算”。当前会显示更明确的表达式卡片，例如：

```text
x1=12 & x2=10 => x3=8
x1=-16 >>s x2=2 => x5=-4
x1=16 + imm=0 => addr=16
```

这些内容是根据当前指令和机器状态动态生成的，不是写死的示例文案。

### 6.3 表达式挂载位置

表达式卡片现在挂载到：

```text
右侧辅助栏 → 机器页 → state-animation-dock
```

也就是机器状态标题上方，方便学生在观察寄存器/内存时同时看到当前计算关系。

### 6.4 OpenHarmony 展示临时让位

如果 OpenHarmony 展示栏当前打开，执行动画时：

```text
state-animation-dock 临时取代 OpenHarmony 展示栏
```

动画结束后：

```text
OpenHarmony 展示栏恢复
```

这样课堂执行指令时不会被 OpenHarmony 信息遮挡，执行结束后仍能继续展示硬件协同视角。

### 6.5 自动切到机器页

执行单步或自动运行时，右侧辅助栏会自动打开并切到“机器”页。

目的：

- 避免用户停留在“代码”或“说明”页时看不到动画。
- 确保执行反馈始终出现在机器状态上下文中。

### 6.6 动画速度

工具栏提供速度选择：

```text
0.5x / 1x / 1.5x
```

当前基础时长已调慢，避免 0.5x 仍看不清的问题。后续仍需根据课堂观感继续调参。

### 6.7 进度显示

执行进度条显示当前指令位置和动画进度，形式保持简洁：

```text
2/5 · 64%
```

同时进度条会随当前指令内部动画同步推进。

## 10. 仍需人工观察的问题

以下内容仍建议继续人工验收：

1. 表达式卡片是否足够醒目，尤其在投影环境下是否能看清。
2. `AND / OR / XOR / SLL / SRL / SRA / lw / sw / branch` 的表达是否都符合教学直觉。
3. 右侧辅助栏自动打开是否会打断用户当前编辑节奏。
4. OpenHarmony 展示临时让位后恢复是否符合预期。
5. Ctrl 多选、框选、批量拖拽在大量积木时是否稳定。
6. 画布拖拽平移是否与积木拖拽手感冲突。
7. 当前 PC 放在顶部进度条旁是否比旧大卡片更利于讲解。

## 11. 后续建议

短期建议优先处理：

1. 对每类指令继续细化表达式模板，尤其是分支、跳转和访存方向。
2. 给表达式卡片加入更明确的阶段文本，例如 `READ / ALU / WRITE / PC`，但不要增加过多中文说明。
3. 继续优化投影可读性：字号、对比度、停留时间。
4. 建立浏览器端 UI 自动化验收，减少每次调整后只能靠人工看页面的问题。
5. 继续拆分 `app/src/app.js`，避免主控制文件继续膨胀。
