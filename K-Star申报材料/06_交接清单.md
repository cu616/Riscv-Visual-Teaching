# K-Star申报与项目维护交接清单

## 原负责人交付

- [ ] 说明各成员在产品设计、Web开发、OpenHarmony适配、文档和答辩中的实际贡献。
- [ ] 确认完整GitHub仓库当前访问权限。
- [x] 提供主办方指定代码仓库地址。
- [ ] 处理当前工作区中尚未提交的有效代码。
- [ ] 明确哪些历史目录不得上传。
- [ ] 整理香橙派RV2真机运行证据并记录运行方式。
- [ ] 提供获奖通知、证书、现场照片和报道链接。
- [ ] 与接手人完成一次项目运行演示。

## 接手人执行

- [ ] 建立独立维护仓库或实验室组织仓库，保留原Git提交历史。
- [ ] 在新仓库README中保留原团队成员和历史来源说明。
- [ ] 设置主分支保护，后续修改通过分支和Pull Request合并。
- [ ] 从全新克隆开始运行Web版和OpenHarmony结构检查。
- [ ] 发布技术博客并回填链接。
- [ ] 寻找主办方获奖公告或学校正式报道。
- [ ] 收集真实的浏览量、Star、Fork、试用反馈或课堂使用记录。
- [ ] 完成K-Star表单并保存提交截图。

## 交接仓库建议

原仓库保留为比赛时期的开发记录。后续维护仓库应专门服务于本项目，不混入其他大创项目。复制时保留Git历史，不使用“下载ZIP后重新初始化”的方式。

## 提交前最后核对

- [ ] 技术博客链接无需登录即可打开。
- [ ] 五项代表成果均能访问，且内容与描述一致。
- [ ] 500字贡献概述没有超过表单限制。
- [ ] 真机、硬件、GPIO和软总线表述与实际完成情况一致。
- [ ] 奖项名称与官方通知一致。
- [ ] 所有个人敏感信息已经移除。
- [ ] 申报人及其他成员同意当前成果归属表述。
