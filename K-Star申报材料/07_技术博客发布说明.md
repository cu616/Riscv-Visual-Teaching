# 技术博客发布说明

## 技术博客是否必须

K-Star“新锐”表单中的“技术博客”带有必填标记，因此需要提供一个可访问的技术博客链接。比赛报道、获奖通知、代码仓库和产品报告可以作为代表成果，但不能稳妥替代技术博客。

现有技术手册和比赛申报文件可以直接复用，不需要从零写。推荐从中提取以下内容，整理成一篇公开文章：

- 教学问题和产品思路；
- 软件模块与指令执行流程；
- OpenHarmony 端工程结构与本地资源加载方式；
- 香橙派 RV2 真机运行过程；
- 遇到的问题、解决方法和复现步骤；
- GitHub 主仓库、AtomGit 公开仓库和比赛提交仓库链接。

本目录中的 `04_技术博客初稿.md` 已经提供文章框架。后续只需要补入真机图片、准确环境信息和公开链接，再发布到 GitHub Pages、公众号、CSDN、知乎或其他可公开访问的平台。

如果时间很紧，可以先把技术博客作为仓库中的独立 Markdown 文章发布，并使用 GitHub 或 AtomGit 文件页面的公开链接填写表单。单独发布到技术内容平台更符合评委对“技术博客”的一般理解，也更便于阅读和传播。

## 图片与公开注意事项

博客可以配少量真机照片或软件截图，用于说明 OpenHarmony 端确实在香橙派 RV2 上运行。图片中不要出现私人邮箱、手机号、设备序列号、签名材料或聊天记录。

演示视频不作为当前提交材料的必要项。若后续审核或宣传需要，可作为补充材料另行整理。
