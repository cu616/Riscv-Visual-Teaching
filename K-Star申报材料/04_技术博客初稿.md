# 从RISC-V可视化教学软件到OpenHarmony设备端适配

第一次接触RISC-V汇编时，学生面对的是一组高度压缩的符号。`rd`、`rs1`、`rs2`、立即数和标签各有位置，一处顺序写错，指令含义就会发生变化。即使汇编格式写对了，寄存器、内存和PC在执行过程中如何变化，也很难从静态课件里看清楚。

我们希望把这段学习过程做成可以操作的教学实验。学生先拼出指令，再观察它如何执行，而不是一开始就被大量语法细节挡住。

## 把指令格式做成可拼接结构

项目的核心界面是一套自研的指令积木。指令主体使用较大的积木表示，寄存器、立即数和标签使用小积木表示。学习者把操作数拖到对应位置后，系统将画布内容解析为结构化指令，并同步生成标准汇编文本。
发布前可在此处插入“指令积木构造界面”截图。

这种设计保留了RISC-V指令格式本身。例如，`lw rd, imm(rs1)`和`sw rs2, imm(rs1)`在界面中保持各自的操作数顺序。学生既能通过积木理解字段作用，也能对照汇编表达，避免教学工具形成另一套与标准脱节的语法。

当前原型覆盖常用算术、逻辑、移位、访存、分支和跳转指令。项目也保留了少量教学伪指令，并在说明中标出它们与基础指令的对应关系。

## 让执行结果能够被观察

完成指令构造后，学习者可以单步执行程序。系统同步展示PC、寄存器和内存状态，被修改的单元会高亮。机器状态还可以切换为十进制、十六进制或二进制，便于讲解位运算、移位和无符号比较。
发布前可在此处插入“寄存器、存储器和 PC 状态变化”截图。

模拟器采用教学抽象模型，重点解释一条指令读取了什么、计算了什么，以及最后修改了什么。它不是完整CPU流水线仿真器，这个边界在产品文档中有明确说明。

## 为什么选择 ArkTS 外壳与 ArkWeb

Windows / Web 原型已经形成了拖拽、吸附、解析和执行闭环。如果直接使用 ArkUI 重写全部交互，短时间内要重新处理大量界面行为，也容易让两个版本产生功能差异。

OpenHarmony 版本采用 Stage 模型工程，在 ArkTS 页面中通过 ArkWeb 加载 rawfile 目录里的本地教学页面。这样可以复用已有的模拟器和交互逻辑，同时把应用纳入 OpenHarmony 工程结构，继续处理设备端资源加载、触控适配和文件接口。

当前工程结构可以概括为：

```text
app/ Web 主线
→ 同步脚本复制静态资源
→ openharmony-port/entry/src/main/resources/rawfile/app/
→ ArkTS 页面创建 ArkWeb
→ ArkWeb 加载本地 index.html
```

工程中预留了运行环境识别、案例保存和导入接口。保存与导入还没有完整接入 OpenHarmony 原生文件选择器，因此不把它描述为已经完成的原生能力。

## 适配中处理的几个实际问题

浏览器中的 HTML5 拖放行为不能直接照搬到 ArkWeb 触控环境。我们在香橙派 RV2 上测试时发现，完整拖拽动画在鼠标路径下容易触发 cpp crash。触屏路径相对可用，但小积木吸附和页面滚动还会互相影响。

OpenHarmony 版本因此采用更稳的输入策略：禁用原生 `draggable` 和 `dataTransfer` 路径，保留自定义触摸/鼠标拖拽，并提供点击选择、点击槽位填入的兜底操作。小积木可以先放到工作台空白区域，再二次拖到目标槽位，也可以从槽位拖出或拖入删除区。

界面布局也单独调过。早期 1024×600 小屏会让左侧素材栏过窄，后续换到 1920×1080 教学屏后，又暴露出顶部工具栏过长、底部日志占空间、右侧辅助栏滚不到底等问题。最终处理方式是把执行日志改为底部抽屉，素材栏和辅助栏支持调整尺寸，机器状态、代码预览和教学说明收进右侧页签。

为了降低主线与移植版之间的维护成本，仓库提供同步脚本，将 Web 主线资源复制到 OpenHarmony rawfile 目录，并恢复移植版需要的桥接脚本和覆盖样式。结构烟测会检查入口页面、脚本依赖和关键文件是否齐全。HDC 部署检查清单则记录 SDK、签名、系统能力和 ArkWeb 加载问题的排查顺序。

## 香橙派RV2在项目中的位置

香橙派RV2是项目面向的OpenHarmony运行设备，也是RISC-V技术路线与教学主题之间的连接点。团队没有修改开发板硬件，也没有把软件模拟的GPIO和LED描述为真实外设控制。
发布前可在此处插入“香橙派 RV2 真机运行”照片或截图。

团队已经完成OpenHarmony版本在香橙派RV2上的真机运行，并保留了证据。正式发布本文前，将从现有照片、安装包和部署记录中选取可以公开的材料，补充设备镜像、安装步骤和实际运行结果。

## 可复现信息

OpenHarmony 移植工程位于仓库的 `openharmony-port/` 目录。每次修改 Web 主线后，建议先运行：

```powershell
npm.cmd run oh:check
```

这个命令会同步 rawfile、生成 ArkWeb 诊断页，并检查 OpenHarmony 版本需要的关键资源。真机部署前，还需要在 DevEco Studio 中确认 SDK、签名、`compatibleSdkVersion`、`releaseType` 和设备侧版本匹配。

本项目中比较容易出错的地方有三处：DevEco SDK 目录结构和 hvigor 预期不一致，HAP 没有签名导致设备拒绝安装，OpenHarmony 专用 CSS 后加载覆盖了主样式。遇到真机显示和 Web 主线不一致时，先查 rawfile 是否同步，再查 `openharmony-port.css` 是否有覆盖规则。
