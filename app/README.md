# RISC-V 指令集可视化教学软件 MVP

当前版本：`v0.3.0`

这是无依赖静态 MVP，用来验证产品核心闭环：

```text
指令积木编辑
→ 结构化指令
→ 汇编预览
→ 教学模拟执行
→ 寄存器 / 内存 / PC 状态变化
→ 数据流动画
→ 教学解释与错误提示
```

## 当前功能

- 支持基础算术：`add`、`sub`、`addi`
- 支持逻辑运算：`and`、`or`、`xor`、`andi`、`ori`、`xori`
- 支持移位运算：`sll`、`srl`、`sra`、`slli`、`srli`、`srai`
- 支持访存：`lw`、`sw`
- 支持条件分支：`beq`、`bne`、`blt`、`bge`、`bltu`、`bgeu`
- 支持跳转：`jal`、`jalr`
- 支持教学伪指令：`j`、`bltz`
- 支持寄存器 `x0` 到 `x31`
- `x0` 恒为 0
- 支持把指令大积木拖到编辑区，再把寄存器 / 立即数 / 标签小积木拼接到接口
- 支持从内置 / 外接摄像头拍照或上传实体积木照片，识别后核对并导入工作台
- 支持立即数槽位键盘输入
- 支持把命名标签贴到任意指令上，并由 `beq` 引用
- 支持内存读写示例
- 支持单步执行、自动执行、暂停、重置
- 支持汇编文本和结构化 JSON 预览
- 支持执行日志与中文教学解释
- 支持独立 CPU 数据通路舞台，分步展示取指、读寄存器、ALU、访存、写回、PC 更新
- 支持预置案例
- 支持 OpenHarmony 硬件积木固化视图，可把工作台中的指令积木和操作数小积木映射成“香橙派软总线 + 星闪链路 + 连接状态识别”的通信框图
- v0.2 增加演示模式、排序辅助线、网格对齐、空接口按拖拽状态显示
- v0.3 扩展常用 RV32I 指令，并增强逻辑、移位、分支、跳转类数据流动画文案

## 当前预置案例

- `立即数赋值`：演示 `addi` 和 `x0` 恒零规则。
- `两数相加`：演示 R 型算术指令。
- `按位逻辑与移位`：演示 `and/or/xor/slli`。
- `掩码与位设置`：演示 `andi/ori/xori`。
- `三类移位对比`：演示 `sll/srl/sra/srli`。
- `内存读写`：演示 `sw` 与 `lw` 的地址计算顺序。
- `条件分支`：演示 `beq` 和命名标签。
- `有符号与无符号分支`：演示 `blt` 与 `bgeu` 的比较差异。
- `无条件跳转`：演示 `jal x0, label`。
- `JAL 保存返回位置`：演示 `jal rd, label` 写回返回位置。
- `教学伪指令`：演示 `j` 与 `bltz` 的教学用途。

## 指令格式注意

当前版本按 RISC-V RV32I 常用格式组织指令：

- `lw rd, imm(rs1)`
- `sw rs2, imm(rs1)`
- `jal rd, label`
- `jalr rd, imm(rs1)`
- `beq/bne/blt/bge/bltu/bgeu rs1, rs2, label`
- `slli/srli/srai rd, rs1, shamt`

其中 `bltz` 和 `j` 标记为教学伪指令：

- `bltz rs1, label` 等价于 `blt rs1, x0, label`
- `j label` 等价于 `jal x0, label`

`sllv` 不是标准 RISC-V RV32I 指令名；如果要表达“变量移位”，请使用 `sll rd, rs1, rs2`。

## 当前交互方式

1. 从左侧拖动 `add`、`addi`、`lw` 等指令大积木到编辑区画布。
2. 指令大积木可以在画布中自由拖动；程序执行顺序按积木的垂直位置从上到下解析。
3. 可拖动素材区和编辑区之间的竖向分隔条，调整各区域宽度。
4. 从左侧生成一个寄存器、立即数或标签小积木，再拖到指令下方对应接口。
5. 指令积木外观为上方一条长方形大积木，下方拼接多个小长方形操作数积木。
6. 小积木不是嵌入表单，而是作为独立矩形贴在指令积木下方，形成上下相邻的拼接效果。
7. 立即数可以在左侧输入生成，也可以在指令的立即数小块里直接键盘输入。
8. 把浅绿色标签小积木贴到某条指令顶部的“标签帽”上，表示该指令拥有这个标签。
9. 对 `beq` 指令，把同名绿色标签小积木拖到 `label` 接口，表示分支目标。
10. 拖动指令积木时会出现排序辅助线；松手后会吸附到画布网格。
11. 点击“演示模式”可隐藏 JSON 细节并放大核心演示区域。

## 实体积木拍摄识别

1. 在“指令编辑区”标题栏点击“拍摄识别”。
2. 选择电脑内置或外接摄像头，也可以直接上传积木照片。
3. 拍照后点击“开始识别”；程序会识别长条指令积木、寄存器块、立即数块和半高标签块。
4. 左上方半高标签会映射为下面指令的定义标签；控制转移指令下方的半高标签会映射为目标标签。
5. 只有检测到白底黑字贴纸的彩色候选块会进入映射；鼠标垫、桌布等没有贴纸的同色背景会被忽略。
6. 参数数量或积木类型不符合指令格式时，结果卡片会以红色显示语法错误，并禁止导入，直到结构修正。
7. 在识别结果区核对指令和参数，选择替换或追加，再应用到工作台。

工作台的标签名与拍照核对使用相同的六个选项：`main`、`loop`、`done`、`target`、`start`、`end`。仅拍摄寄存器或立即数时，识别值会标在照片上；导入程序需要长条指令积木。

软件先定位白底黑字贴纸，再结合贴纸附近的色带和识别出的字形区分指令与操作数。相邻蓝色短块即使连成一条色带，读出的 `x` 寄存器编号也可用于纠正分类。受反光或偏暖光线影响时，软件会用补充候选和字形核对找回贴纸。如果发现一排操作数可能对应漏识别的指令，软件会提示重拍并暂停导入。照片在本机处理，网页内置的 300 个模板覆盖 `pictures/labels` 扫描件中的 25 条已支持基础指令、x0～x31 和立即数 0～31。暂不支持的指令保留待校正状态。

未匹配标签（例如其他立即数、命名标签以及扫描件中没有的 `j` / `bltz`）使用按需加载的浏览器 OCR，首次使用需要网络；组件不可用时保留已经匹配的结果，其余可以手动校正。打印 OCR 保留字形细节和负号，不再使用手写笔画补猜规则。摄像头需要在 `localhost` 或 HTTPS 环境下使用，直接双击 HTML 时建议改用图片上传。

开发时，`scripts/build-printed-labels.mjs` 可从原扫描件重建模板及裁剪清单，需要 `sharp`（可通过 `--sharp-path` 指定模块路径）。`node app/test-printed-labels.mjs --sharp-path <模块路径>` 会以每组第三份扫描样本作为独立测试，并检查 `pictures/1.jpg` 的实际贴纸及轻微旋转、模糊情况。词表和不支持指令的检查已纳入 `npm test`。

`node app/test-vision-browser.mjs --playwright-path <模块路径> --browser <浏览器路径>` 按 `pictures/STATEMENT.txt` 验证 12 张原始照片及图 13～17 的取景区域。图 16 检查反光的绿色访存积木，图 15、17 检查截图标注遮挡字形时的漏行保护和手动核对。半高标签块仍需实拍样本验证。

## 运行方式

在仓库根目录执行：

```powershell
node .\app\server.mjs
```

然后打开：

```text
http://localhost:4173
```

也可以直接用浏览器打开：

```text
app/index.html
```

## 后续迁移方向

当前版本故意不依赖 npm 包，方便快速演示和验收。后续正式工程可以迁移为：

- Electron
- React + TypeScript
- Vite
- Blockly

迁移时优先保留：

- `src/instructions.js` 中的指令定义、解析和汇编格式化思路
- `src/simulator.js` 中的教学模拟器状态设计
- `src/app.js` 中的单步执行、日志、案例和状态联动流程
